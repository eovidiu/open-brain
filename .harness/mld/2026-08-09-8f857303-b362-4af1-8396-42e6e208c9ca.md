## Mistakes
- Asked for a decision the harness had already answered. F015 carries
  `risk: "standard"` and `require_plan_approval: false`, and its own description
  enumerated the two options with enough context to choose. I raised an
  AskUserQuestion anyway; Ovidiu rejected it and re-invoked the skill, which cost
  a round trip. The gate metadata is there precisely so the agent does not have
  to guess whether to ask.
- Touched `cli/src/steps/secrets.ts` without first checking whether it had tests.
  It had none (0% coverage), so the coverage gate turned a three-line deletion
  into an eight-test file. Cheap here, but it should have been priced in at plan
  time rather than discovered at the gate.

## Learnings
- A spec can contradict itself and still read as authoritative. §9.2's validation
  priority listed "HMAC first" as step 1 and "JWT takes precedence" as step 4;
  the handler implemented step 4. Nobody caught it for five months because the
  list was never diffed against the code it described.
- Dead code stays invisible when the docs describe a consumer that never existed.
  §9.2 named MCP `capture_memory` as the JWT branch's client, but that tool
  writes to Postgres directly on both hosts. The documented integration was never
  built, so the branch read as load-bearing.
- The *rationale* field of an ADR is the reusable part. ADR-005's recorded reason
  for rejecting HMAC-only ("one leaked secret compromises all clients") decided
  F015's open question outright — the two options were not equally good once the
  original reasoning was read.
- Distinguish "credential rejected" from "credential store unreachable" in auth
  handlers. Both are non-200; only one means the user should rotate anything.

## Desires
- A check that flags when a file being edited has no test coverage, at edit time
  rather than at the coverage gate. The information exists in the last coverage
  run.
- Something that diffs a numbered procedure in the spec against the branch order
  in the handler it describes. This class of drift (steps renumbered, code not
  updated, or vice versa) is mechanical and went unnoticed for months.
- `init.sh full_test` runs mcp-server and cli only; the four `workers/*` packages
  have to be run by hand. A harness "full test" that omits four of six suites is
  a gate that reports green on a third of the codebase.
